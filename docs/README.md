# Docs

Everything written down about Nerve, and the order to read it in.

**If you are picking up work:** read this page, then `M3-PLAN.md` for what is
next and `LAUNCH-GAP.md` for what is blocking launch. Both carry status
markers, and both are meant to be updated by whoever does the work.

## Keeping these true

A change that ships with stale docs is not finished. The rule of thumb for
what to touch when:

| If you changed | Update |
|---|---|
| A plan item | `M2-PLAN.md` — mark it shipped, say what actually landed and what is still owed by hand |
| The grading rubric or the grade route | Re-run `npm run grade:calibrate`. A rubric change is a calibration change, and the golden set has to be re-scored rather than quietly drifting past the threshold |
| Anything on the blocker list | `LAUNCH-GAP.md` — the entry, its size, and the totals at the top |
| A screen from fixture to real data | `INTEGRATION-GAPS.md` |
| The schema, a policy, or a `db:*` script | `DATA.md` |
| A product rule — rep length, thresholds, what a section is for | `PRODUCT.md`, and record the drift in `LAUNCH-GAP.md` §4 if it now disagrees with the spec |
| A persona dial or contract | `PERSONA.md` |
| A persona's band table, word caps, steering heartbeat, or anything else that composes into what she is told each turn | `PERSONA-AUDIT.md` — mark the defect fixed with what landed, then **re-run `npm run rep:audition`**. A cap is not a cap until it has been auditioned: an uncountable one produced a 40-word median, and a stated one comes back as roughly 1.2x. Compare against an untouched character in the same run, never against M0's gate — that gate was measured on the realtime pipeline and this harness reads higher for everybody |
| A warmth band, the posture clause, or the derived behaviour block | `PERSONA-AUDIT.md` — mark the defect fixed with what landed. Then snapshot `compileInstructions` and re-run the stability harness: **the word caps in `bands.ts` and the `verbosity` rule in `lib/metrics/stability.ts` are one change**, and moving either alone makes the M0 gate read a warmer character as a broken one |
| The audio graph | `AUDIO.md` |
| A price, a plan's rep count, or what a plan includes | `lib/site/plans.ts` — one record feeds `/pricing` and `/profile/subscription`, and §14 has a merchant-of-record reviewer reading the public one. Then `PAYMENTS-NEW-INTEGRATION.md` §11 and `LAUNCH-GAP.md` D2. **`repsPerDay` is enforcement, not copy** — 0 on free is what `consumeRep` and `mayOpenSession` refuse on, and `entitlements.reps_per_day` has to move in the same commit |
| The trial — its length, when the card is charged, or how somebody cancels | `TRIAL_DAYS` and `TRIAL_NOTE` in `lib/site/plans.ts`, the `trial_period_days` on both Whop plans, `lib/email/trial.ts` (the message sent before the charge), **and** `components/site/legal-pages.tsx` — clause 07 of the terms *and* `RefundDocument`, which say the same thing twice and must never disagree. A disputing customer quotes the legal page, and a merchant of record reads the PDF |
| A refund rule, a cancellation behaviour, or anything on a policy PDF | `components/site/legal-pages.tsx` first — clause 07 and `RefundDocument` together — then `npm run legal:pdf` and re-upload to Whop. The uploaded PDF is rendered from the running page, so it cannot drift; but it does not regenerate itself, and Whop serves the file, not the page |
| Who holds a rung, or a new character on the roster | `lib/personas/index.ts` and `npm run db:seed`, then `PERSONA.md`'s ladder table and `PRODUCT.md`. Renumbering the roster renumbers the difficulty curves, because `lib/warmth/levels.ts` reads the map off the roster — check `uiLevel`/`engineRung` stay inverses and that `rankFor` still names the characters its blurbs describe |
| The hero rep on `/` — its script, its voices, or the audio behind it | `scripts/hero-audio.ts` and `LAUNCH-GAP.md` B1. The two sides are captured differently on purpose: his lines are authored and read aloud verbatim, hers must come from the real persona and never from a keyboard |
| Anything a payment reviewer would read — the public pitch, pricing, the legal pages, the safety position | `PAYMENTS-APPROVAL.md` §4, and re-read its §3. A human opens the site during MoR onboarding, and every provider on the shortlist bans dating products by name |
| Anything on the public site — the landing, the method, pricing, the three legal pages | `LAUNCH-GAP.md` B1 and B4, and `site-audit-openai.md` or `VISUAL-AUDIT.md` if it closes or opens a finding there. The site is the second audience §14 names, so a claim added there is a claim somebody will check against the build |
| The canonical URL, the OG image, robots or the sitemap | `lib/site/origin.ts` — one resolver feeds `metadataBase`, `robots.txt` and `sitemap.xml`, and it is the only one of the three allowed to answer `localhost`, in development only. It used to be three fallbacks in three files, one of them localhost, which published link previews nobody outside the build machine could load |
| What is measured — a funnel step, a person trait, where replay may run | `lib/analytics/events.ts` is the catalogue and the rules; `components/analytics.tsx` is the **only** file allowed to import `posthog-js`, the way `lib/voice/provider.ts` is the only voice seam. Two things there are enforcement rather than convention: `safeProps` refuses anything that is not an id, enum, number or boolean, so a transcript turn cannot travel with an event; and `sessionReplayAllowed` is §04's replay rule with tests, so widening where replay runs means changing that function. Then `LAUNCH-GAP.md` B7 |
| A chart's colour or stroke | The rule has to be reachable from the container the component actually renders — `.chart-score` was styled only under `.warmth-chart` and every line on `/progress` was black-on-black for it. `lib/data/progress-chart.test.ts` asserts reachability, not values |
| A sound, a haptic or a beat in the live rep | `lib/audio/kit.ts` is the whole kit and `lib/hooks/use-rep-production.ts` owns the four beats. §02's 400ms ceiling and the "wrap is the quietest sound" rule are assertions in `kit.test.ts`, not notes — the exit sound was authored at 410ms and the test refused it. Haptics: three patterns and no more, because a product with six has one |
| What the user is told to work on | `lib/data/mission.ts` — six missions, derived from `Scorecard.focus`, shown on the scorecard, Train, the brief, the live rep and text mode. **`assertNoScript` refuses a mission that hands over a line**: no quotations, no first person, no cue long enough to read out loud. That guard is the landing page's "we never write your lines" enforced in code, on the one surface positioned to break it |
| The room's ambient bed | `lib/audio/room-tone.ts`, and note the two questions are separate: `roomAcousticsEnabled()` is whether HER VOICE goes through a convolver (no — it hurt intelligibility, `docs/AUDIO.md`), `roomToneAvailable()` is whether the room makes a sound of its own (yes). One flag used to answer both, which is why the bed went silent with the reverb. Beds stay authored in `scenes.ts` |
| A safety rule — what moderation acts on, how the escalation runs, what the age gate accepts | `lib/safety/` is the code and the tests are the argument; then `LAUNCH-GAP.md` B3 and `PAYMENTS-APPROVAL.md` §5.1. A change to what the product refuses is a change to what the three legal pages claim, so `components/site/legal-pages.tsx` is part of the same edit |
| A persona's avatar — its form, its motion, or its place on the colour ramp | `AVATAR-AUDIT.md`, and run `npx vitest run lib/personas/visual.test.ts`: the palette bounds are assertions, not a style note |
| Anything on the onboarding run — a step, its copy, what an answer buys, or the guard that resumes it | `ONBOARDING-AUDIT.md` — mark the item shipped with what landed and what is still owed. A step that is removed or that changes what it collects is also an edit to `components/site/legal-pages.tsx`, because that page lists the setup answers we keep |
| A mark, a diagram, a screenshot, or anything else visual that is not a chart or the persona orb | `VISUAL-AUDIT.md` — mark the finding shipped with what landed. A new glyph goes in `components/marks/index.tsx` **and** its mapping in `lib/marks/registry.ts`, whose test walks the real unions so a rank or dimension without a mark fails the suite. `npm run shots` captures the real app on demand, but **nothing on the site embeds its output** — screenshots on the public pages were tried and taken back out; see the audit's "What was taken back out". **Read its §1 first**: no photographs of people and no drawn characters, because §14's merchant-of-record reviewer opens `/` and every provider on the shortlist bans dating products by name. Volt still appears once per screen, so a mark set is Ink-2 with volt reserved for the current one |
| A retention mechanic — a reward moment, a sheet, a counter, a gate, or anything that changes why somebody comes back | `RETENTION-AUDIT.md` — mark the finding shipped with what landed. **Read its §2 before adding any celebration**: the loud moment is keyed to a personal-best composite rather than to `session.won`, because §07 says outcome is worth zero and a design that detonates on a win is scoring the result. §4 is the list of mechanics that stay refused — no confetti, no leaderboards, no guilt copy, no fourth haptic. A new gate also moves `UNLOCK_RULES` in `lib/data/progression.ts`, and `rankFor` reads tiers *cleared* rather than tiers *open*, so check the rail did not move with it — and `unlockedLevels` closes the ladder **downwards**, so a tier below an open one stays open however its own gate reads. A tier's copy lives in `lib/data/level-copy.ts` and is read both by the unlock sheet and by the roster's locked section, so it cannot promise one thing before the gate and another after |
| A one-time sheet, or a beat that fires once ever | `components/modals.tsx`, and check which stamp gates it. `nerve:first-loss-seen` and `nerve.scorecard.explained` are **one explanation behind two doors** — `markScoringExplained` writes both and both gates read both, because §12 only ever wanted the "outcome is worth zero" argument made once. `scripts/shots.ts` stamps every one of these seen before it captures, so a renamed key silently starts capturing modals |
| An email the product sends unprompted, or its schedule | `lib/data/nudge.ts` for the rules and the copy — pure and tested: an evening window one hour wide (an `hour >=` condition fires again at 20:00, 21:00 and midnight), a streak of at least two, never on a day already claimed, at most one a day, and asserted never to threaten the streak, because §4 of `RETENTION-AUDIT.md` rules out guilt copy. `lib/db/nudge.ts` sends it and stamps `ui_flags` **before** the send, since a missed nudge is recoverable and a duplicate is not. `.github/workflows/cron.yml` is what calls it, and `LAUNCH-GAP.md`'s weekly-cron entry says which two secrets turn the whole thing on |

`NERVE-SPEC.md` is **not** edited as the build moves. It is v1.0 and it is the
thing we are measuring against; where the build has deliberately diverged, that
is recorded in `LAUNCH-GAP.md` §4 rather than by quietly rewriting the target.
