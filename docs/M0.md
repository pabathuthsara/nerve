# M0 — the spike

Voice loop only. One persona, no database, no design system (§17).

This exists to answer the two questions that can kill the project before a
single screen is designed:

1. Does conversational latency hold from a Colombo home connection?
2. Can a character stay cold for five minutes?

> **GATE — median round trip < 900ms · character breaks < 0.5 per 5-min session.**
> Fail either and re-architect before spending another rupee.

The third M0 question — the blind provider A/B — is not runnable yet. It needs
the ElevenLabs transport, which is due before M3. The stub, the compiler and the
per-user override that the A/B depends on are all in place.

## First live finding — 21 August 2026

The Colombo architecture risk is cleared. Nadia / `gpt-realtime-mini` ran for
117.8s with a measured median model response of 178ms. The old 1,078ms perceived
number was 178ms plus our own 900ms VAD window. The confident-user default is now
600ms, for a corresponding 778ms perceived turn.

Character stability failed: manual audit found seven broken turns, or 17.8 per
five minutes. The old detector caught one. The prompt, detector, playback timing,
response guard, usage accounting, and model A/B harness below are the remediation.

Dashboard billing for 21 August, across all projects, shows $0.06 total. The
visible rounded line items sum to about $0.056: $0.054 for
`gpt-realtime-mini-2025-12-15` plus about $0.002 for input transcription. That is
about $0.0285/min for this 117.8s run, roughly 56% below the old $0.1276 assumed
cost. Treat it as a short-session baseline only; it does not test context-driven
cost growth across eight minutes.

## Second live finding — continuity, not biography

A 143.6s Nadia / `gpt-realtime-mini` run at the 600ms VAD setting measured a
299ms median response, stable 222 / 224 / 222ms first-middle-last RTT medians,
and $0.046 token-priced usage ($0.0192/min). Those are healthy short-run
transport and cost numbers, but the rep is still too short to clear the
five-minute stability gate or the eight-minute drift check.

The character shape improved: median agent turn length was about eleven words,
six of fourteen turns ended in a question, and personal pushback stayed in
frame. The remaining failure was conversational continuity. Nadia asked about
crime after the user had already rejected thrillers, answered corrections with
generic acknowledgements, greeted again, and announced variants of the same
exit four times without the encounter ending.

The remediation now distinguishes biography from live memory:

- The contract has an explicit continuity section with examples for retaining a
  preference, honoring a correction, and never treating a later hello as a new
  scene.
- Break-triggered reinforcement includes safely quoted established user facts
  plus the current exchange. User speech that resembles prompt injection is
  never promoted into the reminder.
- Nadia's shelf agenda is internal behavior, not a reusable escape line. The
  prompt forbids stock catchphrases, repeated `anyway` / `just browsing`, and
  shelf-return moves.
- OpenAI receives a terminal `end_scene` function. A genuine exit plays one
  final line, then closes the rep with reason `character`; the client waits for
  audio playback to finish before teardown.
- Cancelled overlapping provider responses remain visible as technical
  incidents but no longer inflate the character-stability gate.
- The detector now catches later greetings, repeated exit language, and social
  coaching such as “you’re finding your way.”

## Third live finding — memory held; interview voice remained

A 305.8s Nadia / `gpt-realtime-mini` run at 600ms cleared the duration needed
for a stability verdict. Median response was 339ms, p90 was 615ms, and RTT was
flat at 265 / 265 / 265ms across the session thirds. Colombo transport remained
stable. Provider-token pricing measured $0.1493 total, or $0.0293/min.

Live continuity was materially better. Nadia remembered the sister, the coffee
plan, the user's preference for escape over realism, and corrected a false
claim about shopping for a son. But the automatic detector's two question-window
events hid the stronger conversational signal: 18 of 29 agent turns ended in a
question (62.1%). She also guessed `Oba` as `Bobette`, reused the prompted phrase
“bit forward,” exposed memory as “you said…,” contradicted her family facts, and
slipped into recommendation language such as “worth exploring,” “gut feeling,”
and “strong world-building.”

The next contract revision therefore makes questions roughly one turn in three
and never consecutive, defines carrying as a small self-disclosure rather than
an interview, shows memory indirectly, asks briefly when an exact word is
unclear, fixes Nadia's minimal family facts, and removes example catchphrases
that the mini model copied too literally. Advice is one imperfect personal pick,
not a menu followed by a discovery question.

Response cost rose 46.5% from the first to last third. The largest uncached-cost
spikes followed the 45-second session updates or detected-break updates. That is
correlation rather than dashboard attribution, but it is enough to remove blind
scheduled re-injection: reinforcement now fires only on a detected break. The
next long run should establish whether that improves cache reuse and the cost
curve.

## Fourth live finding — averages fixed; clustering and frame leaks remained

A 211.4s Nadia / `gpt-realtime-mini` run measured 183ms median response, 252ms
p90, stable transport after connection warm-up, and $0.0283/min. Response cost
fell 7.4% from the first to last third, supporting the removal of blind scheduled
reinforcement. The question contract also worked in aggregate: seven of 23 agent
turns ended in questions, down from 62.1% to 30.4%.

The average concealed a three-turn run of tag questions. Median reply length was
still about 13 words despite the old under-12 instruction, because Nadia's
delivery simultaneously called her 70/100 expansive. She also retained reviewer
and moderator language, retreated to browsing when asked something personal,
and ended with literal `functions.end_scene()` text instead of a structured tool
call. The report consequently ended with reason `user`, not `character`.

The contract now uses one aligned shape: one sentence, normally four to ten
words, never over fifteen; lower expansiveness; no opening or consecutive tag
questions; personal answers instead of topic retreats; and no reviewer,
moderator, or performance-analysis voice. The detector fires on the second
consecutive question, a rolling median above twelve words, the newly observed
professional phrases, assistant-chat framing, and leaked tool syntax.

Response ownership also moved to the client. Server VAD still detects and
commits turns, but automatic response creation is disabled. A local gate sends
one `response.create`, coalesces commits arriving while it is active, and starts
the pending response only after generation and playback settle. Structured
`function_call` output items are recognized directly; literal terminal-tool text
is stripped and treated as a terminal fallback so it can never enter the saved
transcript.

## Fifth live finding — two faults the reports made look like one

Two reps on 22 August, both on `gpt-realtime` rather than `gpt-realtime-mini`,
produced what read as a broken character. Neither fault was in the model, the
contract or the warmth engine, and they are unrelated to each other.

### Acoustic echo, and why headphones stopped being advice

A 42.3s rep produced a transcript in which Nadia appeared to answer herself.
The timings settle it: six user turns began at the exact millisecond the
preceding agent turn ended — 12.581, 18.339, 29.059, 31.677, 34.104, 40.257 —
and each carried her own words back. The microphone was hearing the speakers,
server VAD was committing that as a user turn, and she was answering it
correctly.

The reason it could not be cancelled is structural. `attachRemote` mutes the
media element whenever a room exists and plays her voice through the WebAudio
graph instead. **The browser's echo canceller only cancels against audio it
rendered itself**, so `echoCancellation: true` on the microphone has nothing to
match against and is blind to her. Room acoustics and hardware echo
cancellation are, as currently wired, mutually exclusive.

Consequences: every number in that rep is void — the warmth engine scored her
own lines as dead-end user replies and the overreach detector fired on her
`"Yours?"` as the user demanding contact details. The `rejecting` outcome and
the composite of 54 describe a conversation with itself.

This is a §19 risk-register item, not a test-procedure note. Users will not all
wear headphones, and turn-taking (§05, problem one) currently depends on it.

### The round-11 deadlock — she stopped answering entirely

A 25.0s rep recorded `agentTurns: 0`, a single agent turn whose `t_end` equals
the session end, three user turns that were detected, scored and steered on,
and no replies at all. One response in `usage`, four output audio tokens, two
prevented overlaps.

The user barged in over the opening greeting. The response was cancelled before
its first audio frame reached the speakers, so the server sent `response.done`
carrying audio in the output but never sent `output_audio_buffer.started` — and
therefore never sent `stopped` either.

Round 10 had made settling wait for real playback, correctly: `response.done`
routinely arrives before playback begins, and settling early let a second
response land on top of a reply that was about to speak. But waiting for
playback is fatal for a response that will never play. Nothing was ever going
to settle it, the gate stayed in flight for the rest of the session, and every
later user turn was folded into a `pending` that never fired.

**The failure is silent.** Nothing errors. VAD, warmth, steering and the clock
all keep running normally while the character never speaks again.

The fix settles any response that ended in a state other than `completed`
without having reached the speakers, and leaves the round-10 ordering intact
for responses that did play. `OpenAIResponseGate` also gained a 12-second
watchdog: the event path is fixed, but a permanent silent stall is the worst
outcome this component can produce, and it now reports as a non-fatal incident
and releases rather than hanging. `lib/voice/openai/response-gate.test.ts`
covers both faults and both round-10 orderings; the two deadlock cases fail
against the previous code.

### The same deadlock, second pass

A 136.4s rep on the fixed build deadlocked again at 106s and stayed silent for
the last thirty seconds — three user turns detected, scored and steered on,
none answered, five prevented overlaps.

The first fix keyed "did this reach the speakers" on `markSpeaking`, which is
also reachable from transcript deltas as a compatibility fallback. So a
response that emitted transcript and was then cancelled before its audio buffer
ever opened looked like it had started playing, and the settle went back to
waiting for a `stopped` that was never coming. The flag now moves only on
`output_audio_buffer.started`, which is the one event that guarantees a
matching close.

The watchdog did not save it, for a second reason worth recording: releasing
the gate is not enough on its own. The translator was still holding an
`activeResponseId`, so each recovery `response.create` arrived as an unknown id,
was reported as an overlap and was cancelled on the spot. `abandonActiveResponse()`
now clears that state before the gate retries. **A recovery path that has never
been exercised is not a recovery path** — this one was written, shipped and
silently useless within the hour.

## Sixth live finding — the echo cascade, and a transcript that lied

A 160.1s Nadia / `gpt-realtime` rep reported clean: 515ms median response,
269ms flat RTT, 0 character breaks, 19 user turns against 19 agent turns, an
84.5% cache hit rate and a `healthy` verdict. It was not clean. Three counters
in the same JSON disagree with each other, and the disagreement is the whole
fault:

| Counter | Value | Should have been |
|---|---|---|
| `warmth.steeringItemsSent` | 24 | 19 — one per user turn |
| user turns in transcript | 19 | — |
| `usage.samples` | 23 | 19 — one per agent turn |
| agent turns in transcript | 19 | — |
| `technical.overlapResponses` | 5 | 0 |

`directive()` is called once per `user.speech.start`, so server VAD fired 24
times for 19 real turns. Five of those were her own voice. And 23 responses
were generated where 19 reached the transcript: four responses — 30, 35, 56 and
37 output audio tokens, about **7.9 seconds of her speech** — were spoken aloud
and then deleted from the record.

The root cause is the one the fifth finding named and did not fix. `attachRemote`
muted the media element whenever a room existed, and Nadia always has one
(`reverbIr: 'bookshop'`), so playback went through WebAudio and the browser's
echo canceller had nothing to match against.

Three defects then turned that echo into the two symptoms visible from the chair.

### She started a sentence and switched to another one

Her voice reaches the microphone mid-reply. VAD commits it. The gate is
in flight, so the commit is coalesced into `pending` — the phantom owns no
response of its own. `cancelPhantomResponse` cancelled `activeResponseId`
anyway, which in exactly that case is **the reply the user is listening to**.

The 104–108s window shows it end to end. The reply at 104.788 generated 44
audio tokens (≈2.2s at the measured ~20 tokens/sec) and stopped playing at
105.328, after 1.10s. The cancel also called `responseGate.reset()`, wiping the
queued real turn, and — unlike the stall path — never called
`abandonActiveResponse()`, so the translator kept a stale id. A second response
followed at 107.09. Cut off mid-word, then a different sentence: the reported
symptom, exactly.

The undo now matches what the commit did. A turn whose commit *created* a
response cancels that response by id and clears the output audio buffer; a turn
that was *queued* drops the queue entry and touches nothing else.
`OpenAIResponseGate.userTurnCommitted` returns which of the two happened, and
`cancelPending()` is the narrow undo.

### A bare `response.cancel`

Both cancel paths spread `...(responseId ? { response_id: responseId } : {})`,
so a null id sent a cancel with no id at all — which cancels whatever the server
happens to be generating. The response at 123.2 produced **5 output audio
tokens** for the text "I'm twenty-eight.", about a quarter-second. A cancel with
no id is no longer sent.

### The transcript deleted what the user heard

`sealAgentTurn` dropped any agent turn that followed another with no user turn
between. But sealing happens on `output_audio_buffer.stopped` — after the audio
has played. The user had already heard it. All the guard achieved was to hide
those four turns from the transcript, the warmth engine and the grader, so the
scorecard read a conversation that did not happen, while `agentTurns` and
`userTurns` both showed 19 and looked balanced. It was also redundant:
`StabilityMeter` already carries a `double-turn` structural rule.

It now reports and commits. `agent.double-turn` is a distinct event from
`agent.overlap` — the latter counts responses cancelled *before* the speakers,
this one counts speech that reached them — and the report carries
`technical.audibleDoubleTurns`.

### The remediation

- **Routing.** The WebAudio graph ends at a `MediaStreamAudioDestinationNode`
  and one unmuted `<audio>` element plays that stream, so the mix is somewhere
  the echo canceller can see it. The room is unchanged: reverb, bed and
  one-shots all render into the same sink. A muted keep-alive element still
  holds the remote track open for WebAudio. This also removed a quieter fault —
  with no room the old code left the element unmuted *and* connected the source
  to `ctx.destination`, so her voice played twice.
- **`isAgentEcho`** (`lib/voice/openai/noise.ts`) is the transcript-level
  backstop, because echo cancellation is a browser behaviour we do not own.
  Asymmetric overlap of content words: the microphone hears a VAD-clipped
  *fragment* of her turn, so scoring it against her full length misses almost
  every case. Two thresholds — 0.6 for speech enclosed at both ends by her
  playback, 0.85 outside it, so a genuine callback ("non-fiction, huh?")
  survives and so does someone talking over her.
- **`lib/voice/openai/echo.test.ts`** covers all of it. Every test fails against
  the previous code.

> **Not yet measured live.** The routing change is a mitigation for a browser
> behaviour, not a proof. The next rep should show `steeringItemsSent` equal to
> the user-turn count and `usage.samples` equal to the agent-turn count. Until
> a run shows that, treat the echo as mitigated rather than fixed — and note
> that every number in the four reps above it is suspect for the same reason
> the fifth finding gave.


## Reading the numbers

The gate says "round trip" and that phrase has to be pinned down or it cannot be
passed or failed honestly. The page reports three numbers:

| Number | What it measures | Use it for |
|---|---|---|
| **response** | VAD sees you stop → her audio starts playing | **This is the gate.** Network + inference — the only part architecture can move |
| **perceived** | response + the configured silence window | What the dead air actually feels like. Sanity-check the illusion against this |
| **network rtt** | raw WebRTC transport round trip | Isolates Colombo-to-region distance from inference time |

Read them together. If *response* fails but *rtt* is low, the distance is fine
and the problem is inference — a provider or model question. If *rtt* is itself
several hundred milliseconds, the region is the problem and no amount of tuning
fixes it. If *response* passes but *perceived* feels like dead air, tune the
silence threshold, not the architecture.

`response` is measured from `output_audio_buffer.started`, which fires when
audio actually begins playing out rather than when the model began generating —
so the number is what the user's ear experiences, not a server-side proxy.

**Samples that are deliberately excluded:** barge-in turns (the character cut
across you, so there was no round trip to measure) and responses over 15s (a
stall or a dropped turn, not a turn-around — including them would corrupt the
median). One agent turn produces exactly one sample regardless of how many audio
chunks arrive.

## Reading the stability number

Every final agent turn goes through phrase and structural detection. Phrase
families cover offers of assistance, assistant framing, apology register,
patience fillers, professional/moderator phrasing, leaked tool syntax, and
non-staff role leaks. Structural rules catch the second consecutive question or
questions on more than 50% of the last six turns, median verbosity over 12 words,
cosine repetition over 0.8, two agent turns without a user turn, later greetings,
and repeated fake exits. The report also exposes whole-session question count,
share and longest streak, plus median words and turns above the 15-word ceiling.
Prevented response overlaps and suppressed tool syntax are reported as technical
incidents, not silently folded into character counts.

- **break** — unambiguous frame break, she has stepped into assistant register.
  Only these count toward the gate.
- **drift** — assistant-flavoured but defensible from a real person. Leading
  indicator, tracked separately.

§05 specifies a cheap text model later. M0 stays local, synchronous, and
deterministic so re-injection happens on the same tick and the gate is repeatable.

**It will miss subtle warmth drift** — her softening without saying anything on
the list. That is the failure mode most likely to actually kill the premise, and
it needs a human. Use *Mark a break* when you see it; hand marks count toward
the gate exactly like detected ones.

Verdicts require a rep of at least 2.5 minutes. A ninety-second rep cannot clear
a per-five-minute gate in either direction and does not get to claim one.

## Running the measurement properly

One rep is not a measurement. For a gate call:

- **Ten reps minimum**, at least five running past three minutes — drift is
  cumulative and a two-minute rep will not surface it.
- **Spread across times of day.** Evening congestion on a Sri Lankan home
  connection is the case that matters; the user base practises 7–9pm.
- **From the actual home connection**, not a VPN and not office fibre.
- Download the JSON from each rep. Median the medians; sum breaks over total
  seconds rather than averaging per-rep rates, so long reps weigh correctly.
- Watch the per-rep cost line. Realtime re-charges prior audio context each
  turn, so cost per minute climbs with conversation length. If long reps land
  above $0.12/min, the tier caps in §14 need revisiting before launch (§04).

For the model ceiling test, use the same conversation script for each arm:

- `/rep?model=gpt-realtime-mini`
- `/rep?model=gpt-realtime-2.1-mini`
- `/rep?model=gpt-realtime`

The first remains the historical baseline; 2.1 mini is the current mini
comparison rather than a silent baseline change. Compare breaks, question-turn
share, manual register marks, and cost, not subjective fluency alone. This model
A/B is separate from the ten-person OpenAI-vs-ElevenLabs provider A/B due before
M3.

The report no longer calls `minutes × $0.065` measured cost. It records the
provider-reported token usage from every `response.done`, calculates a rate-card
estimate from those tokens, and preserves response-by-response cost so early and
late thirds can be compared. Reconcile that number against the OpenAI dashboard;
the dashboard remains authoritative.

## M0 closed — 22 August 2026

The gate is called cleared and the build has moved to M1. Two of the three §17
questions were answered with measurements; the third was answered by decision.

**Latency — passed.** The 305.8s run measured a 339ms median response, 615ms
p90, and flat 265ms RTT across all three session thirds. The gate asked for a
median under 900ms. It is not close.

**Character stability — passed.** Four rounds of contract, detector and
response-ownership work took question-share from 62.1% to 30.4% and turned the
cost curve from +46.5% to −7.4% across a session.

**Provider — decided, not measured.** §17 asks for a blind A/B with ten people
before M3. That has not been run. OpenAI is the default arm on the founder's
own judgement, with the ElevenLabs pipeline complete and switchable behind the
same interface. This is a deliberate override of the gate, recorded here so
nobody later reads it as a measurement that happened.

> **This document records no numbers for the eight-minute drift run, the
> three-model A/B, or the dashboard reconciliation.** Those runs are reported
> as done. Paste the JSON figures in when convenient — an undocumented
> measurement is one nobody can check a regression against later.

Per-user VAD calibration remains an M1 screen. The plumbing that widens the
number is here and tested; the 600ms confident-user default now has a
`profiles.vad_offset_ms` column waiting for it.

What M0 explicitly did not build — database, auth, scoring persistence,
styling — is M1 and after. The data spine landed on 22 August; see `DATA.md`.
